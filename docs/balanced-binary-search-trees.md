# 균형 이진 탐색 트리

# 개요

**균형 이진 탐색 트리(balanced binary search tree)** 는 삽입과 삭제를 거듭해도 높이가 원소 수의 로그에 머무르는 이진 탐색 트리다. 탐색, 삽입, 삭제, 그리고 정렬 순서로 인접한 원소를 찾는 연산이 모두 $O(\log n)$ 에 끝난다.

높이를 유지하는 수단은 회전이다. 회전은 키의 순서를 바꾸지 않고 부모와 자식의 자리를 바꾸는 상수 시간 연산이며, 어떤 불변량을 회전으로 복구하는지가 자료구조의 종류를 가른다.

# 직관

정렬된 배열에서 값을 찾는 데는 이진 탐색으로 $\lceil\log_2 n\rceil$ 번 비교하면 된다. 그런데 값 하나를 끼워 넣으려면 뒤의 원소를 모두 한 칸씩 밀어야 하므로 $n$ 번 쓰기가 필요하다. 연결 리스트로 바꾸면 끼워 넣기는 포인터 두 개만 고치면 되지만, 중간으로 건너뛸 수 없어 찾는 데 $n$ 번 비교가 필요하다.

두 연산을 함께 빠르게 하려면 비교로 범위를 반씩 줄이면서도 삽입이 국소적이어야 한다. 각 노드에 키를 하나 두고, 왼쪽 부분 트리에는 그보다 작은 키만, 오른쪽에는 큰 키만 놓는다. 찾을 값을 루트의 키와 비교해 한쪽으로만 내려가면 비교 한 번에 한 부분 트리가 버려지고, 삽입은 내려간 끝에 노드를 매달면 끝난다. 걸음 수는 트리의 높이다.

키를 $1,2,3,\dots,n$ 순서로 넣어 보면 이 방법이 막힌다. 매번 오른쪽으로만 내려가므로 노드가 한 줄로 늘어서고 높이가 $n$ 이 된다. 탐색이 다시 $n$ 번 비교가 되어 연결 리스트와 같아진다.

높이가 커진 원인은 삽입 순서가 트리의 모양을 그대로 정한 것이다. 그래서 삽입할 때마다 모양을 고친다. 노드 $x$ 와 그 왼쪽 자식 $y$ 를 두고, $y$ 를 위로 올리고 $x$ 를 $y$ 의 오른쪽 자식으로 내리면서 $y$ 의 오른쪽 부분 트리를 $x$ 의 왼쪽에 붙인다. 이 조작 뒤에도 왼쪽이 작고 오른쪽이 큰 조건이 그대로 성립하고, 고치는 포인터는 세 개뿐이다. $x$ 쪽 높이가 하나 줄고 $y$ 쪽이 하나 늘므로, 한쪽으로 치우친 부분을 이 조작으로 되돌릴 수 있다.

남은 문제는 언제 고칠지를 정하는 것이다. 각 노드에 두 자식의 높이 차가 $1$ 을 넘지 않는다는 조건을 붙이고 삽입 경로를 거슬러 올라가며 어긋난 자리마다 회전하면, 높이는 항상 $\log_2 n$ 의 상수배 안에 있다.

# 정의

## 이진 탐색 트리

**이진 탐색 트리(binary search tree)** 는 각 노드가 전순서 집합의 키 하나와 왼쪽, 오른쪽 자식을 갖는 트리이며, 모든 노드 $v$ 에 대해 왼쪽 부분 트리의 키가 $v$ 의 키보다 작고 오른쪽 부분 트리의 키가 크다는 조건을 만족한다. 키의 비교에는 [부분순서](partial-orders.md)의 특수한 경우인 전순서를 쓴다.

중위 순회는 키를 오름차순으로 내놓는다. 노드 수가 $n$ 이고 높이가 $h$ 이면 탐색, 삽입, 삭제는 모두 $O(h)$ 이고 $h$ 는 $\lceil\log_2(n+1)\rceil$ 과 $n$ 사이의 값이다.

## 회전

회전은 중위 순회 순서를 보존하면서 부모와 자식을 교환한다.

```javascript
// x 의 왼쪽 자식 y 를 x 의 자리로 올린다. 키 순서는 보존된다.
function rotateRight(x) {
  const y = x.left;
  x.left = y.right;
  y.right = x;
  return y; // 새 부분 트리의 뿌리
}
```

$y$ 의 오른쪽 부분 트리에 담긴 키는 $y$ 보다 크고 $x$ 보다 작으므로, 회전 뒤 $x$ 의 왼쪽에 놓여도 조건이 유지된다. `rotateLeft` 는 좌우를 바꾼 것이다.

## 높이 균형

**AVL 트리(Adelson-Velsky–Landis tree)** 는 모든 노드에서 두 자식의 높이 차가 $1$ 이하라는 조건을 유지하는 이진 탐색 트리다. 각 노드에 그 차이를 $-1,0,1$ 로 저장하고, 삽입이나 삭제로 차이가 $\pm 2$ 가 된 자리에서 회전 한 번이나 두 번으로 조건을 복구한다.

## 색 균형

**red-black 트리(red-black tree)** 는 각 노드에 붉은색이나 검은색을 주고 다음 셋을 유지한다.

- 뿌리와 모든 잎(비어 있는 자리)은 검다.
- 붉은 노드의 두 자식은 검다.
- 어떤 노드에서 그 아래 모든 잎까지의 경로에 있는 검은 노드의 수가 같다.

세 번째 조건의 공통값이 검은 높이다. 붉은 노드가 연속할 수 없으므로 실제 높이는 검은 높이의 두 배를 넘지 않는다.

# 성질

## 높이 한계

노드가 $n$ 개인 AVL 트리의 높이 $h$ 는 다음을 만족한다.

$$
h\lt 1.4405\log_2(n+2)-0.3277
$$

*증명의 요지.* 높이 $h$ 인 AVL 트리의 최소 노드 수를 $N(h)$ 라 하면 두 자식의 높이가 $h-1$ 과 $h-2$ 일 때가 최소이므로 $N(h)=N(h-1)+N(h-2)+1$ 이고 $N(0)=1$, $N(1)=2$ 다. 이 점화식의 해는 Fibonacci 수(Fibonacci number) $F$ 로 $N(h)=F_{h+3}-1$ 이다. $F_k$ 가 황금비 $\varphi$ 의 거듭제곱으로 커지므로 $n\ge N(h)$ 에서 $h$ 의 상한이 $\log_\varphi n$ 꼴로 나오고 $1/\log_2\varphi=1.4405$ 다.

red-black 트리에서는 $h\le 2\log_2(n+1)$ 이다. 검은 높이가 $b$ 이면 모든 경로에 검은 노드가 $b$ 개 있어 노드 수가 $2^b-1$ 이상이고, 실제 높이가 $2b$ 이하다.

## 연산 비용

삽입과 삭제는 내려가는 경로의 길이에 비례하는 비교를 하고, 거슬러 올라가며 회전한다. AVL 삽입은 회전을 최대 두 번 하고, red-black 삽입은 최대 두 번, 삭제는 최대 세 번 한다. 색이나 높이 차를 고치는 작업은 경로를 따라 올라가므로 $O(\log n)$ 이다.

## 분할상환 분석과 splay 트리

splay 트리(splay tree)는 균형 조건을 저장하지 않는다. 접근한 노드를 회전으로 뿌리까지 올리기만 한다. 한 연산의 최악 비용은 $O(n)$ 이지만, 비어 있는 트리에서 시작한 $m$ 번의 연산 전체 비용이 $O((m+n)\log n)$ 이다[^1].

*증명의 요지.* 노드 $v$ 의 부분 트리 크기를 $s(v)$ 라 하고 포텐셜을 $\Phi=\sum_v\log_2 s(v)$ 로 둔다. 노드를 두 단계씩 올리는 회전에서 실제 비용과 포텐셜 변화의 합이 뿌리까지의 크기 비의 로그로 억제되고, 그 합이 $3\log_2 n+1$ 이하다. 포텐셜은 항상 $0$ 이상이고 처음 값이 $O(n\log n)$ 이므로 전체 비용의 상한이 나온다.

## 비교 기반 하한

키를 비교로만 다루는 자료구조에서 탐색 비용은 $\log_2 n$ 보다 작아질 수 없다. 비교 한 번이 두 갈래를 주므로 $n$ 개를 가르는 [결정 트리](comparison-sorting.md)의 높이가 $\log_2 n$ 이상이다. 위 상한들이 상수배 안에서 최적이다.

# 활용

- **경로 질의 자료구조.** [Link-cut tree](link-cut-trees.md)는 숲을 경로로 쪼개 각 경로를 splay 트리에 담고, splay 의 [분할상환](amortized-analysis.md) 성질로 [동적 연결성](dynamic-connectivity.md) 질의를 로그 시간에 처리한다.
- **순서 통계와 구간 합.** 각 노드에 부분 트리의 크기나 키의 합을 저장하면 $k$ 번째 원소 찾기와 구간 합 질의가 같은 경로 길이에 끝난다. 회전이 세 포인터만 고치므로 이 값들도 상수 시간에 갱신된다.
- **우선순위 큐의 대체.** 최솟값은 가장 왼쪽 노드이므로 추출이 $O(\log n)$ 이다. 임의 키 삭제와 범위 질의가 함께 필요하면 [이진 힙](binary-heaps.md) 대신 쓴다.

[^1]: D. D. Sleator and R. E. Tarjan, Self-adjusting binary search trees, *Journal of the Association for Computing Machinery* 32(3), 1985, 652–686. 포텐셜 함수로 splay 의 분할상환 비용을 유도한다.
