# Rice 정리

# 개요

**Rice 정리(Rice's theorem)** 는 프로그램이 무엇을 계산하는지에 관한 질문 가운데 모든 프로그램에서 답이 같지는 않은 것은 모두 기계적으로 판정할 수 없다는 정리다. 주어진 프로그램이 모든 입력에 $0$ 을 내는지 판정하는 프로그램이 있다면, 그것으로 임의의 프로그램이 멈추는지도 판정할 수 있어 [정지 문제](halting-problem.md)가 결정 불가능하다는 사실과 모순이다. Rice 정리는 이 환원을 프로그램이 계산하는 함수에만 의존하는 모든 성질에 대해 한 번에 하고, 프로그램 검사 도구가 정확한 답 대신 근사를 쓰는 근거가 된다.

# 직관

프로그램을 받아 "이 프로그램은 모든 입력에 $0$ 을 내는가" 에 답하는 검사기를 만들려 한다. 코드가 `return 0` 한 줄이면 읽기만 해도 답이 나온다. 코드가 반복문을 돌다가 $0$ 을 내면, 반복이 끝나는지부터 알아야 한다.

다음 프로그램 $N$ 을 본다. $N$ 은 입력 $x$ 를 받으면 먼저 정해진 프로그램 $M$ 을 정해진 입력 $w$ 에 돌리고, 그것이 끝나면 $0$ 을 낸다. $M(w)$ 가 멈추면 $N$ 은 모든 입력에 $0$ 을 내고, 멈추지 않으면 어느 입력에도 답을 내지 않는다. 검사기가 $N$ 에 답하려면 $M(w)$ 가 멈추는지에 답해야 한다.

이 구성은 "모든 입력에 $0$ 을 낸다" 의 자리에 다른 질문을 넣어도 그대로 성립한다. 쓰인 것은 질문이 $N$ 이 내는 값에만 관계된다는 것뿐이다. "코드에 `goto` 가 있는가" 처럼 코드의 모양을 묻는 질문에는 이 구성이 쓰이지 않고, 코드를 훑으면 답이 나온다.

# 정의

## 의미론적 성질

프로그램 $e$ 가 계산하는 [계산 가능](computability.md) 부분함수를 $\varphi_e$ 라 한다. 어떤 입력에서 멈추지 않으면 그 입력의 함숫값은 정의되지 않는다.

프로그램의 성질 $P$ 가 $\varphi_e = \varphi_{e'}$ 이면 $P(e)$ 와 $P(e')$ 가 같은 성질이면 **의미론적 성질(semantic property)** 이라 한다. 그렇지 않은 성질을 **구문적 성질(syntactic property)** 이라 한다. 의미론적 성질은 계산 가능 부분함수의 성질로 보아 $P(\varphi_e)$ 로 쓴다.

직관 절의 "모든 입력에 $0$ 을 낸다" 와 "항등함수를 계산한다" 는 의미론적 성질이다. "코드에 `goto` 가 있다" 는 구문적 성질이다. `goto` 를 쓴 프로그램과 쓰지 않은 프로그램이 같은 함수를 계산할 수 있다.

## 비자명성과 지표집합

의미론적 성질 $P$ 를 만족하는 계산 가능 부분함수와 만족하지 않는 것이 모두 있으면 $P$ 는 **비자명(nontrivial)** 하다. "모든 입력에 $0$ 을 낸다" 는 상수함수 $0$ 이 만족하고 항등함수가 만족하지 않으므로 비자명하다. "계산 가능한 부분함수를 계산한다" 는 모든 프로그램이 만족하므로 자명하고, 항상 "예" 를 출력하는 알고리즘이 판정한다.

의미론적 성질 $P$ 의 **지표집합(index set)** 은 다음이다.

$$
I_P=\lbrace e:P(\varphi_e)\rbrace
$$

직관 절의 프로그램 $N$ 의 번호는 $M(w)$ 가 멈출 때만 "모든 입력에 $0$ 을 낸다" 의 지표집합에 든다.

# 성질

## 결정 불가능성

비자명한 의미론적 성질 $P$ 에 대해 $I_P$ 의 소속 여부를 모든 프로그램에서 항상 멈추며 정확히 판정하는 알고리즘은 없다.

증명의 요지. 어디에서도 정의되지 않는 부분함수를 $\bot$ 라 하자. 필요하면 $P$ 의 부정을 취해 $P(\bot)$ 가 거짓이라고 놓는다. 비자명성으로 $P(g)$ 가 참인 계산 가능 부분함수 $g$ 를 고를 수 있다.

프로그램 $M$ 과 고정 입력 $w$ 에서 다음 프로그램 $N$ 을 만든다. $N$ 은 입력 $x$ 를 받으면 먼저 $M(w)$ 를 실행하고, 그것이 멈춘 뒤 $g(x)$ 를 실행한다.

$$
\varphi_N=
\begin{cases}
g,&M(w)\text{ halts},\cr
\bot,&M(w)\text{ does not halt}.
\end{cases}
$$

$M(w)$ 가 멈추지 않으면 $N$ 은 어떤 입력에서도 결과를 내지 못하므로 $\varphi_N = \bot$ 다. 따라서 $P$ 의 판정기가 있다면 $N$ 을 검사해 $M(w)$ 의 정지를 판정할 수 있고, 정지 문제의 결정 불가능성에 모순이다.

이 논증은 $(M,w)$ 에서 $N$ 을 만드는 과정이 계산 가능할 것을 요구한다. $N$ 의 코드는 $M$, $w$, $g$ 의 코드를 정해진 틀에 이어 붙여 얻으므로 이 과정은 계산 가능하다.

## 적용 예

| 성질 | 의미론적? | 결정 가능? |
|---|---|---|
| 모든 입력에서 멈춘다 | 예, 비자명 | 아니오 |
| 항상 $0$ 을 반환한다 | 예, 비자명 | 아니오 |
| 이 프로그램과 같은 함수를 계산한다 | 예, 비자명 | 아니오 |
| 소스에 특정 문자열이 있다 | 아니오 (구문적) | 예 |
| 실행이 100 단계 안에 끝난다 | 아니오 (자원 의존) | 예 |
| 계산 가능한 함수를 계산한다 | 예, 자명 | 예 |

셋째 줄이 프로그램 동치 판정이고, 컴파일러 최적화의 정당성 검증과 코드 중복 탐지가 여기 걸린다. 넷째와 다섯째 줄은 의미론적이지 않으므로 정리의 대상이 아니며 실제로 결정 가능하다.

의미론적이지 않다고 자동으로 결정 가능한 것은 아니다. 정리는 한쪽 방향의 함의만 준다.

## 인식 가능성

$I_P$ 가 결정 가능하지 않아도 인식 가능할 수는 있다. "어떤 입력에서 멈춘다" 는 성질은 프로그램을 모든 입력에 대해 병렬로 돌리면 참인 경우 유한 시간에 확인된다.

어떤 의미론적 성질이 인식 가능한지를 정확히 특징짓는 것이 [Rice–Shapiro 정리](rice-shapiro-theorem.md)다. 대략 "유한한 양의 정보만 보고 확인할 수 있는 성질" 만 인식 가능하며, "모든 입력에서 멈춘다" 처럼 무한한 확인이 필요한 성질은 인식 가능하지도 않다.

# 활용

## 정적 분석의 설계 원칙

"이 프로그램이 널을 역참조하는가", "이 변수는 항상 양수인가", "이 코드가 도달 가능한가" 는 모두 의미론적이고 비자명하다. 따라서 완전하고 항상 종료하는 검사기는 존재하지 않는다.

실제 도구는 셋 중 하나를 포기한다. 완전성을 포기해 거짓 경보를 감수하거나, 종료성을 포기해 시간 제한을 두거나, 답을 항상 내는 대신 "모름" 을 허용한다. 타입 검사기와 [추상해석](abstract-interpretation.md)은 첫째를 택해 안전하지만 거부되는 프로그램이 생기고, 모델 검사기는 상태 공간을 유한하게 제한해 문제 자체를 바꾼다.

## 언어 설계

표현력을 낮추면 결정 가능한 성질이 생긴다. 전체 함수만 쓸 수 있는 언어에서는 종료가 보장되고, 정규표현식과 [문맥 자유 문법](context-free-grammars.md)에서는 여러 성질이 결정 가능하다. 설정 파일 형식, 질의 언어, 스마트 계약 언어는 이 때문에 Turing 완전성(Turing completeness)을 의도적으로 피한다.

## 개별 프로그램의 검증

정리가 배제하는 것은 모든 프로그램에 대해 항상 답을 내는 하나의 알고리즘이다. 특정 프로그램이 종료함을, 특정 함수가 항상 $0$ 을 반환함을 증명하는 일은 가능하다. 증명 보조 도구와 형식 검증은 이 구분 위에 선다. 사람이 증명을 제공하고 기계가 그것을 검사한다.[^1]

[^1]: Boaz Barak, *Introduction to Theoretical Computer Science*, Universality and uncomputability, Rice's Theorem 절. 의미론적 성질의 정의와 정지 문제 환원. https://introtcs.org/public/lec_08_uncomputability.html
