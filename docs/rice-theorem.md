# Rice 정리

# 개요

[정지 문제](computability.md)는 하나의 문제가 결정 불가능함을 보였다. 그것만으로는 "정지 여부는 특별히 어려운 질문이고 다른 것은 괜찮지 않을까" 라는 기대가 남는다.

Rice 정리는 그 기대를 없앤다. 프로그램이 무엇을 계산하는지에 대한 질문이라면, 자명하지 않은 한 전부 결정 불가능하다. 정지 여부, 항상 $0$ 을 반환하는지, 특정 입력에서 오류를 내는지, 두 프로그램이 같은 함수를 계산하는지가 모두 하나의 정리로 처리된다.

결론이 이렇게 광범위한 것은 가정이 강하기 때문이다. 성질이 코드가 아니라 계산하는 함수에만 의존해야 한다는 조건이 그것이며, 이 조건이 정확히 어디까지 적용되는지를 아는 것이 이 정리를 실무에서 쓰는 요령이다.

# 직관

## 무엇을 묻느냐가 아니라 어떻게 묻느냐

정리가 배제하는 것은 "프로그램이 계산하는 함수" 에 대한 질문이다. "소스 코드에 `goto` 가 있는가" 는 코드를 훑으면 답이 나오고 결정 가능하다. 같은 함수를 계산하는 두 프로그램이 다른 답을 받을 수 있으므로 의미론적 성질이 아니다.

반면 "이 프로그램이 항등함수를 계산하는가" 는 의미론적이다. 코드가 어떻게 생겼든 결과가 같으면 답이 같아야 한다. 그리고 이런 질문은 자명하지 않은 한 전부 결정 불가능하다.

이 구분이 정적 분석 도구의 설계에 그대로 반영된다. 문법적 검사는 완전하게 자동화할 수 있고, 의미론적 검사는 근사할 수밖에 없다.

## 자명함이 빠져나가는 유일한 구멍

모든 계산 가능 부분함수가 만족하거나 아무도 만족하지 않는 성질은 결정 가능하다. 항상 "예" 또는 항상 "아니오" 를 출력하면 되기 때문이다. 정리가 제외하는 것이 이 두 경우뿐이다.

그래서 "그 성질은 자명한가" 가 정리를 적용하기 전에 확인할 유일한 조건이 된다. 대개 두 예를 제시하면 끝난다. 성질을 만족하는 프로그램 하나와 만족하지 않는 프로그램 하나다.

# 정의

## 의미론적 성질

프로그램 $e$ 가 계산하는 부분함수를 $\varphi_e$ 라 한다. 어떤 입력에서 멈추지 않으면 그 입력의 함수값은 정의되지 않는다.

성질 $P$ 가 코드 모양이 아니라 부분함수만으로 결정되면 의미론적 성질이다. 곧 $\varphi_e = \varphi_{e'}$ 이면 $P(\varphi_e)$ 와 $P(\varphi_{e'})$ 가 같아야 한다.

$P$ 를 만족하는 계산 가능 부분함수와 만족하지 않는 것이 모두 있으면 $P$ 는 비자명하다.

## 정리

비자명한 의미론적 성질 $P$ 에 대해

$$
I_P=\{e:P(\varphi_e)\}
$$

의 소속 여부를 모든 프로그램에서 항상 멈추며 정확히 판정하는 알고리즘은 없다.

# 성질

## 증명

어디에서도 정의되지 않는 부분함수를 $\bot$ 라 하자. 필요하면 $P$ 의 부정을 취해 $P(\bot)$ 가 거짓이라고 놓는다. 비자명성으로 $P(g)$ 가 참인 계산 가능 부분함수 $g$ 를 고를 수 있다.

프로그램 $M$ 과 고정 입력 $w$ 에서 다음 프로그램 $N$ 을 효과적으로 만든다. $N$ 은 입력 $x$ 를 받으면 먼저 $M(w)$ 를 실행하고, 그것이 멈춘 뒤 $g(x)$ 를 실행한다.

$$
\varphi_N=
\begin{cases}
g,&M(w)\text{ halts},\\
\bot,&M(w)\text{ does not halt}.
\end{cases}
$$

$M(w)$ 가 멈추지 않으면 $N$ 은 어떤 입력에서도 결과를 내지 못하므로 $\varphi_N = \bot$ 다. 따라서 $P$ 의 판정기가 있다면 $N$ 을 검사해 $M(w)$ 의 정지를 판정할 수 있고, 정지 문제의 결정 불가능성에 모순이다.

$N$ 을 만드는 과정이 계산 가능해야 한다는 점이 핵심이며, 이는 프로그램을 데이터로 다루는 능력에서 나온다. 같은 능력이 정지 문제의 대각선 논증에도 쓰였다.

## 적용 예

| 성질 | 의미론적? | 결정 가능? |
|---|---|---|
| 모든 입력에서 멈춘다 | 예, 비자명 | 아니오 |
| 항상 $0$ 을 반환한다 | 예, 비자명 | 아니오 |
| 이 프로그램과 같은 함수를 계산한다 | 예, 비자명 | 아니오 |
| 소스에 특정 문자열이 있다 | 아니오 (문법적) | 예 |
| 실행이 100 단계 안에 끝난다 | 아니오 (자원 의존) | 예 |
| 계산 가능한 함수를 계산한다 | 예, 자명 | 예 |

셋째 줄이 프로그램 동치 판정이고, 컴파일러 최적화의 정당성 검증과 코드 중복 탐지가 여기 걸린다. 넷째와 다섯째 줄은 의미론적이지 않으므로 정리의 대상이 아니며 실제로 결정 가능하다.

의미론적이지 않다고 자동으로 결정 가능한 것은 아니다. 정리는 한쪽 방향의 함의만 준다.

## 인식 가능성

$I_P$ 가 결정 가능하지 않아도 인식 가능할 수는 있다. "어떤 입력에서 멈춘다" 는 성질은 프로그램을 모든 입력에 대해 병렬로 돌리면 참인 경우 유한 시간에 확인된다.

어떤 의미론적 성질이 인식 가능한지를 정확히 특징짓는 것이 Rice–Shapiro 정리다. 대략 "유한한 양의 정보만 보고 확인할 수 있는 성질" 만 인식 가능하며, "모든 입력에서 멈춘다" 처럼 무한한 확인이 필요한 성질은 인식 가능하지도 않다.

```python
# Rice 정리가 말하는 것을 흉내로 확인할 수는 없다. 대신 판정기를 만들려는
# 시도가 어떻게 자기 자신에게 걸리는지를 구조로 보인다.

def build_N(M, w, g):
    """M(w) 가 멈추면 g 를, 아니면 어디서도 안 멈추는 함수를 계산하는 N."""
    def N(x):
        M(w)          # 여기서 멈추지 않으면 아래로 내려가지 못한다
        return g(x)
    return N


def decides_always_zero(prog):
    """'항상 0 을 반환하는가' 를 판정한다고 가정하는 자리."""
    raise NotImplementedError("Rice 정리에 의해 존재하지 않는다")


g = lambda x: 0                      # P(g) 참: 항상 0
halts = lambda w: None               # 즉시 멈춤
loops = lambda w: [None for _ in iter(int, 1)]   # 멈추지 않음

N1 = build_N(halts, "w", g)
print(N1(5))                         # 0: phi_N1 = g 이므로 P 참

# N2 = build_N(loops, "w", g); N2(5) 는 영원히 멈추지 않는다 -> phi_N2 = bot
# decides_always_zero(N1) 과 decides_always_zero(N2) 가 다르므로,
# 그런 판정기가 있으면 loops 의 정지를 판정하게 된다.
try:
    decides_always_zero(N1)
except NotImplementedError as e:
    print(e)
```

`build_N` 이 환원 그 자체다. 판정기가 있다고 가정하면 그것을 $N$ 에 적용해 $M(w)$ 의 정지를 읽어 낼 수 있고, 그 불가능성이 판정기의 부재를 강제한다.

# 활용

## 정적 분석의 설계 원칙

"이 프로그램이 널을 역참조하는가", "이 변수는 항상 양수인가", "이 코드가 도달 가능한가" 는 모두 의미론적이고 비자명하다. 따라서 완전하고 항상 종료하는 검사기는 존재하지 않는다.

실제 도구는 셋 중 하나를 포기한다. 완전성을 포기해 거짓 경보를 감수하거나, 종료성을 포기해 시간 제한을 두거나, 답을 항상 내는 대신 "모름" 을 허용한다. 타입 검사기는 첫째를 택해 안전하지만 거부되는 프로그램이 생기고, 모델 검사기는 상태 공간을 유한하게 제한해 문제 자체를 바꾼다.

## 언어 설계

표현력을 낮추면 판정 가능성이 돌아온다. 전체 함수만 쓸 수 있는 언어에서는 종료가 보장되고, 정규표현식과 문맥자유 문법에서는 여러 성질이 결정 가능하다. 설정 파일 형식, 질의 언어, 스마트 계약 언어가 의도적으로 튜링 완전성을 피하는 이유가 이것이다.

Rice 정리는 그 거래의 경계를 알려 준다. 튜링 완전성을 유지하는 한 자동 판정은 원리적으로 불가능하며, 무언가를 자동으로 보장하고 싶으면 표현력을 내려놓아야 한다.

## 오해하지 말 것

정리는 개별 프로그램의 성질을 증명할 수 없다고 말하지 않는다. 특정 프로그램이 종료함을, 특정 함수가 항상 $0$ 을 반환함을 증명하는 일은 얼마든지 가능하다. 불가능한 것은 모든 프로그램에 대해 항상 답을 내는 하나의 알고리즘이다. 증명 보조 도구와 형식 검증이 성립하는 것도 이 구분 덕분이며, 사람이 증명을 제공하고 기계가 검사하는 분업이 여기서 나온다.[^1]

[^1]: Boaz Barak, *Introduction to Theoretical Computer Science*, Universality and uncomputability, Rice's Theorem 절. 의미론적 성질의 정의와 정지 문제 환원. https://introtcs.org/public/lec_08_uncomputability.html
