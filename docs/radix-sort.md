# 기수 정렬

# 개요

**기수 정렬(radix sort)** 은 정수 키를 진법의 자릿수로 나누고, 가장 낮은 자리부터 한 자리씩 계수 정렬(counting sort)로 안정하게 정렬하기를 되풀이하는 정렬 알고리즘이다. 키가 $b$ 진법으로 $d$ 자리이면 $O(d(n+b))$ 시간이 든다. 키의 값을 배열의 위치로 쓰므로 [비교 정렬](comparison-sorting.md)의 하한 $\Omega(n\log n)$ 이 적용되지 않는다.

# 직관

세 자리 수 $329, 457, 657, 839, 436, 720, 355$ 를 정렬한다. 일의 자리만 보고 정렬하되, 일의 자리가 같은 수끼리는 원래 순서를 지킨다. 결과는 $720, 355, 436, 457, 657, 329, 839$ 다. 이어서 십의 자리로 같은 방법을 쓰면 $720, 329, 436, 839, 355, 457, 657$ 이 된다.

십의 자리가 같은 $436$ 과 $839$ 사이의 순서, $355, 457, 657$ 사이의 순서는 앞 단계에서 정한 일의 자리 순서 그대로다. 그래서 두 단계가 끝나면 아래 두 자리로 정렬되어 있다. 백의 자리로 한 번 더 하면 $329, 355, 436, 457, 657, 720, 839$ 로 정렬이 끝난다. 수끼리는 한 번도 비교하지 않았고, 자리마다 $0$ 부터 $9$ 까지의 칸에 나눠 담기만 했다.

# 정의

## 안정성

정렬 알고리즘이 **안정(stable)** 하다는 것은 키가 같은 원소들의 출력 순서가 입력 순서와 같다는 것이다.

## 계수 정렬

**계수 정렬(counting sort)** 은 $0$ 이상 $b$ 미만의 정수 키를 가진 원소 $n$ 개를 다음과 같이 정렬한다. 키마다 개수를 세고, 개수의 누적합으로 키 $c$ 인 원소들이 출력에서 시작할 자리 $\mathrm{start}\lbrack c\rbrack$ 를 정한 뒤, 입력을 앞에서부터 읽어 각 원소를 그 키의 다음 빈자리에 둔다. $O(n+b)$ 시간이 들고 안정하다.

## 기수 정렬

키를 $b$ 진법으로 $d$ 자리 $x=\sum_{j=0}^{d-1}x_j b^j$ 로 쓴다. 기수 정렬은 $j=0,1,\dots,d-1$ 의 순서로 자리 $x_j$ 를 키로 삼아 계수 정렬한다.

```typescript
function countingSortBy(a: number[], key: (x: number) => number, b: number): number[] {
  const start = new Array<number>(b + 1).fill(0);
  for (const x of a) start[key(x) + 1]++;
  for (let c = 0; c < b; c++) start[c + 1] += start[c];
  const out = new Array<number>(a.length);
  for (const x of a) out[start[key(x)]++] = x;
  return out;
}

function radixSort(a: number[], b: number, d: number): number[] {
  let p = 1;
  for (let j = 0; j < d; j++) {
    const q = p;
    a = countingSortBy(a, (x) => Math.floor(x / q) % b, b);
    p *= b;
  }
  return a;
}
```

# 성질

## 정확성

정리. 단계 $j$ 가 끝나면 원소들은 아래 $j+1$ 자리가 나타내는 수 $x\bmod b^{j+1}$ 의 순서로 정렬되어 있다[^1].

증명의 요지. $j$ 에 대한 귀납법이다. 단계 $j$ 에서 두 원소의 자리 $x_j$ 가 다르면 이 단계의 정렬이 순서를 정하고, 그 순서가 $x\bmod b^{j+1}$ 의 순서와 같다. $x_j$ 가 같으면 계수 정렬이 안정하므로 앞 단계의 순서, 곧 $x\bmod b^j$ 의 순서가 남는다. 각 단계가 안정하지 않으면 이 논증이 성립하지 않는다.

## 시간과 진법의 선택

정리. $0$ 이상 $n^c$ 미만의 정수 $n$ 개는 $O(cn)$ 시간에 정렬된다.

증명의 요지. 기수 정렬은 단계마다 $O(n+b)$ 시간이므로 전체 $O(d(n+b))$ 다. 진법을 $b=n$ 으로 잡으면 $n^c$ 미만의 수는 $d=c$ 자리이고 시간은 $O(c(n+n))$ 이다.

$b$ 가 크면 단계 수가 줄고 단계마다 비용이 는다. $w$ 비트 키에서 $b=2^r$ 로 잡으면 단계가 $\lceil w/r\rceil$ 개이고, $r$ 을 $\log_2 n$ 근처로 두면 시간이 $O(nw/\log n)$ 이다.

## 높은 자리부터의 기수 정렬

가장 높은 자리로 원소를 $b$ 개의 무리로 나누고 무리마다 다음 자리로 재귀하는 방법도 있다. 이 재귀의 호출 구조는 키들을 $b$ 진 자릿수열로 본 [트라이](tries.md)와 같고, 원소가 하나 남은 무리에서 멈추면 키를 구별하는 데 필요한 자리까지만 읽는다. 문자열을 사전순으로 정렬할 때 이 방법을 쓴다.

# 활용

- [접미사 배열](suffix-arrays.md)의 접두사 배가. 단계마다 순위의 쌍을 정렬하는데, 순위가 $0$ 이상 $n$ 이하의 정수이므로 두 자리 기수 정렬로 $O(n)$ 시간에 한다.
- 정수와 고정 길이 키의 정렬. 키 길이가 정해진 정수, 날짜, 고정 길이 문자열은 비교 정렬보다 적은 연산으로 정렬된다.
- 카드 분류기. Hollerith 의 천공 카드 분류기는 카드 묶음을 한 열의 구멍 위치로 열두 칸에 나누는 기계였고, 낮은 열부터 차례로 나누어 정렬했다[^1].

[^1]: D. E. Knuth, *The Art of Computer Programming, Vol. 3: Sorting and Searching*, 2nd ed., Addison-Wesley, 1998, §5.2.5.
