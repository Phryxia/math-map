# 스킵 리스트

# 개요

**스킵 리스트(skip list)** 는 정렬된 연결 목록을 여러 층으로 쌓고 원소마다 동전 던지기로 정한 높이까지의 층에 넣어, 찾기와 삽입과 삭제를 기대 $O(\log n)$ 시간에 하는 자료구조다. Pugh 가 1990 년에 제안했다[^1].

[균형 이진 탐색 트리](balanced-binary-search-trees.md)는 회전으로 높이를 유지하고, 스킵 리스트는 무작위로 고른 높이로 같은 연산 시간을 기댓값으로 얻는다. 시간의 분석은 [유한 확률 공간](probability.md)의 독립인 동전 던지기에 대한 계산이다.

# 직관

정렬된 연결 목록에서 키를 찾으면 앞에서부터 하나씩 지나가야 해서 원소가 $n$ 개면 $n$ 단계가 든다. 원소를 하나 걸러 하나씩 뽑아 위층 목록을 만들면 위층에서 $n/2$ 단계로 키 근처까지 간 뒤 아래층에서 한 단계를 더 간다. 위층에서 다시 하나 걸러 하나씩 뽑기를 반복하면 층이 $\log\_2 n$ 개가 되고 층마다 한두 단계씩만 가므로 찾기가 $O(\log n)$ 단계에 끝난다.

이 규칙대로라면 원소 하나를 넣을 때마다 "하나 걸러 하나" 의 배치가 깨져 위층을 전부 다시 만들어야 한다. 그래서 원소마다 위층에 올릴지를 동전으로 정한다. 앞면이 나오는 동안 한 층씩 올리면 층 $i$ 에는 평균 $n/2^i$ 개가 남고, 넣을 때 다른 원소의 높이를 건드릴 필요가 없다. 이렇게 쌓은 목록이 스킵 리스트다.

# 정의

## 층과 높이

원소 $x$ 의 높이 $\mathrm{ht}(x)$ 는 독립인 동전 던지기로 정한다. $\Pr\lbrack\mathrm{ht}(x)\ge i\rbrack=2^{-i}$ 이다. 층 $i$ 는 높이가 $i$ 이상인 원소들을 키 순서로 이은 연결 목록이고, 모든 층의 맨 앞에는 키 $-\infty$ 의 머리 마디가 있다. 원소의 마디들은 층 사이에서 아래 방향으로도 이어져 있다.

## 찾기

가장 높은 층의 머리에서 시작한다. 다음 마디의 키가 찾는 키 $a$ 보다 작으면 오른쪽으로 가고, 아니면 한 층 내려간다. 층 $0$ 에서 멈춘 자리의 다음 마디가 $a$ 이상인 첫 원소다.

```typescript
interface SkipNode {
  key: number;
  next: (SkipNode | null)[]; // next[i] 는 층 i 의 다음 마디
}

function search(head: SkipNode, a: number): SkipNode | null {
  let x = head;
  for (let i = head.next.length - 1; i >= 0; i--) {
    let nx = x.next[i];
    while (nx !== null && nx.key < a) {
      x = nx;
      nx = x.next[i];
    }
  }
  return x.next[0];
}
```

삽입은 찾기에서 층마다 멈춘 마디를 기억해 두고, 새 원소의 높이를 던진 뒤 그 높이까지의 층마다 기억한 마디 뒤에 끼운다. 삭제는 같은 방법으로 층마다 빼낸다.

# 성질

## 높이

$n$ 개 원소 가운데 높이가 $c\log\_2 n$ 이상인 것이 있을 확률은 합집합 상한(union bound)으로 $n\cdot 2^{-c\log\_2 n}=n^{1-c}$ 이하다. 그래서 층 수는 높은 확률로 $O(\log n)$ 이다. 원소 하나의 마디 수의 기댓값은 $\sum\_{i\ge 0}2^{-i}=2$ 이므로 전체 공간의 기댓값은 $2n$ 이다.

## 찾기 경로의 기대 길이

정리. 찾기 경로의 단계 수의 기댓값은 $2\log\_2 n+O(1)$ 이하다[^1].

증명의 요지. 경로를 끝에서부터 거꾸로 따라간다. 거꾸로 가는 경로의 각 마디에서, 그 원소가 한 층 더 높으면 위로 가고 아니면 왼쪽으로 간다. 동전이 독립이므로 각 마디에서 위로 갈 확률은 $1/2$ 이고, 한 층을 오르는 데 드는 단계 수의 기댓값은 $2$ 다. 층 $\log\_2 n$ 까지 오르는 데 기댓값 $2\log\_2 n$ 단계가 들고, 그 위의 층에 있는 원소 수의 기댓값은 상수다.

삽입과 삭제는 찾기 경로를 따라 층마다 상수 개의 포인터를 바꾸므로 기대 시간이 같은 차수다.

# 활용

- 정렬된 사전. 키 순서의 범위 질의와 순위 질의가 필요한 메모리 내 사전이 스킵 리스트를 쓴다. Redis 의 정렬 집합이 그 예다.
- 동시성 자료구조. 삽입이 국소적인 포인터 몇 개만 바꾸고 회전이 없으므로, 여러 스레드가 잠금 없이 비교 후 교환(compare-and-swap) 연산으로 갱신하는 사전을 만들기 쉽다[^2].
- 저장 엔진. 디스크에 쓰기 전에 최근 쓰기를 메모리에 정렬된 채 모아 두는 표를 스킵 리스트로 둔다.

[^1]: W. Pugh, "Skip lists: a probabilistic alternative to balanced trees", Communications of the ACM 33 (1990), 668–676.
[^2]: K. Fraser, *Practical lock-freedom*, PhD thesis, University of Cambridge, 2004.
