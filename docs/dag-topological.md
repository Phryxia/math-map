# DAG와 위상정렬

# 개요

"A 를 끝내야 B 를 시작할 수 있다" 는 제약이 잔뜩 있을 때 전체를 어떤 순서로 처리해야 하는가. 빌드 시스템, 패키지 설치, 강의 수강, 스프레드시트 재계산, 그리고 이 지도의 문서 구조가 모두 같은 질문을 던진다.

제약을 방향 간선으로 그리면 방향 그래프가 되고, 순환이 없으면 DAG 다. 위상정렬은 그런 그래프의 정점을 모든 간선이 앞에서 뒤로 향하도록 일렬로 세우는 것이다. [그래프](graphs.md)의 언어로 표현되지만 내용은 [부분순서](partial-orders.md)의 선형 확장과 같다. 두 관점을 오가는 것이 이 주제를 이해하는 핵심이고, 존재성은 순서론이 알려 주고 효율적 계산은 그래프 알고리즘이 알려 준다.

# 직관

## 순환이 있으면 순서가 없다

순환을 따라가면 순번이 계속 커지다가 시작점으로 돌아와야 한다. 자기 자신보다 큰 수는 없으므로 불가능하다. 반대로 순환이 없으면 언제나 "아직 아무것도 기다리지 않는" 정점이 있고, 그것부터 꺼내면 된다.

이 둘이 합쳐져 "위상정렬이 존재한다 ⟺ DAG 다" 가 된다. 그래서 위상정렬 알고리즘은 정렬기이면서 동시에 순환 검출기다. 정점을 전부 꺼내지 못하고 멈추면 남은 부분에 순환이 있다.

## 부분순서와 같은 것

DAG 에서 도달 가능성 관계는 부분순서이고, 거꾸로 유한 부분순서의 Hasse 도형은 DAG 다. 위상정렬은 순서론에서 선형 확장이라 부르는 것과 정확히 같다.

이 대응에서 나오는 중요한 귀결이 하나 있다. 선형 확장이 보통 여럿이므로 위상정렬도 유일하지 않다. `A → C`, `B → C` 이면 `A B C` 와 `B A C` 가 모두 정답이다. 정렬 결과 하나를 유일한 정답처럼 다루면 안 되고, 알고리즘이 바뀌면 출력도 바뀔 수 있다. 위상정렬이 유일한 것과 결과 순서가 Hamilton 경로를 이루는 것, 곧 전체가 하나의 사슬인 것은 동치다.

## 직접 간선과 도달 가능성

`A → B`, `B → C` 이면 `A` 에서 `C` 로 도달할 수 있지만 직접 간선이 있어야 하는 것은 아니다. 추이 폐포는 도달 가능한 모든 쌍을 간선으로 채운 그래프이고, 추이 축약은 반대로 없어도 되는 간선을 전부 지운 최소 그래프다. DAG 에서는 추이 축약이 유일하며 그것이 Hasse 도형이다.

이 지도의 간선 규칙도 같은 발상이다. 부모가 다른 부모의 조상이면 그 간선은 도달 가능성으로 이미 따라오므로 빼는 편이 낫다.

# 정의

## DAG

DAG 는 directed acyclic graph 의 약어로 방향 순환이 없는 방향 그래프다. 여기서 위상이라는 말은 열린집합을 다루는 위상수학과 무관하며, 그래프의 배치를 뜻하는 옛 용법이다.

## 위상정렬

유한 방향 그래프 `G = (V, E)`, `|V| = n` 에 대해 위상정렬은 각 정점에 `1` 부터 `n` 까지 서로 다른 순번을 주는 함수 `τ` 로서

$$
(u,v)\in E\Rightarrow\tau(u)<\tau(v)
$$

를 만족한다. 진입차수는 그 정점으로 들어오는 간선의 수다.

# 성질

## 존재 정리

유한 방향 그래프가 위상정렬을 가지는 것과 DAG 인 것은 동치다.

순환이 있으면 순번이 순환을 따라 증가하다 시작점으로 돌아와 모순이다. 역으로 비어 있지 않은 유한 DAG 에는 진입차수 `0` 인 정점이 있다. 없다면 들어오는 간선을 거꾸로 계속 따라갈 수 있고, 정점이 유한하므로 언젠가 같은 정점을 다시 만나 순환이 생긴다.

## Kahn 알고리즘

진입차수 `0` 인 정점을 꺼내 결과 뒤에 붙이고 그 정점에서 나가는 간선을 지우는 과정을 반복한다. 전부 꺼내면 위상정렬이고, 남은 정점이 있는데 꺼낼 수 없으면 순환이 있다.

인접 리스트와 큐를 쓰면 각 정점과 간선을 상수 횟수만 처리하므로 간선 수를 `m` 이라 할 때 시간 복잡도는

$$
O(n+m)
$$

이다. 큐 대신 우선순위 큐를 쓰면 사전순으로 가장 앞선 위상정렬을 얻을 수 있고, 이때 `O((n+m)log n)` 이 된다.

```python
from collections import deque

def toposort(n, edges):
    """0..n-1 정점, edges 는 (u, v) 목록. 순환이 있으면 None."""
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indeg[v] += 1
    q = deque(v for v in range(n) if indeg[v] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == n else None


# A=0, B=1, C=2:  A->C, B->C
print(toposort(3, [(0, 2), (1, 2)]))      # [0, 1, 2]
print(toposort(3, [(0, 1), (1, 2), (2, 0)]))   # None: 순환
```

DFS 로 구현하면 후위 순회 순서를 뒤집은 것이 위상정렬이고, 회색 정점으로 되돌아가는 간선이 순환을 알려 준다. 두 구현은 출력 순서가 다를 수 있지만 둘 다 올바른 위상정렬이다.

## 위상순이 주는 것

위상정렬된 순서로 정점을 훑으면 각 정점을 처리할 때 그 선행 정점들이 이미 끝나 있다. 이 성질 덕분에 DAG 위의 여러 문제가 한 번의 선형 순회로 풀린다.

| 문제 | 방법 |
|---|---|
| 최장 경로 | 위상순으로 `dp[v] = max(dp[u]+w)` |
| 최단 경로 (음수 가중치 허용) | 같은 점화식, 음수여도 무방 |
| 경로 개수 | `cnt[v] = Σ cnt[u]` |
| 도달 가능성 | 역위상순으로 비트집합 합집합 |

일반 그래프에서 최장 경로는 NP-난해인데 DAG 에서는 선형 시간이다. 순환이 없다는 조건 하나가 문제의 난이도를 완전히 바꾼다. [동적 계획법](dynamic-programming.md)의 상태 그래프가 DAG 여야 하는 이유도 같다. 부분문제 의존 관계에 순환이 있으면 계산 순서를 정할 수 없다.

## 임계 경로

작업마다 소요 시간이 있을 때 최장 경로가 전체 완료 시간의 하한이고, 이를 임계 경로라 한다. 임계 경로 위의 작업이 하나라도 지연되면 전체가 지연되므로 일정 관리의 초점이 된다.

부분순서의 언어로는 최대 사슬의 길이다. 대응하는 최대 반사슬이 동시에 실행할 수 있는 작업의 최대 개수이며, 이 두 값이 서로를 결정한다는 것이 Dilworth 와 Mirsky 정리의 내용이다.

## 간선 추가와 순환

DAG 에 간선 `(u, v)` 를 추가해도 순환이 생기지 않는 것과, `v` 에서 `u` 로 가는 경로가 없는 것은 동치다. 따라서 검사는 `v` 에서 출발하는 도달 가능성 탐색 한 번이면 된다.

간선이 계속 추가되는 상황에서는 매번 전체를 다시 정렬하는 대신 순번을 국소적으로 고치는 온라인 위상정렬 기법이 쓰인다. 기존 순번이 이미 `τ(u) < τ(v)` 를 만족하면 아무것도 할 필요가 없고, 어긋날 때만 두 순번 사이의 구간을 재배치한다.

# 활용

## 의존성 해소

빌드 시스템은 파일 의존 그래프를, 패키지 관리자는 라이브러리 의존 그래프를, 스프레드시트는 셀 참조 그래프를 위상정렬한다. 순환이 발견되면 각각 순환 의존 오류, 설치 불가, 순환 참조 경고로 보고한다. 사용자에게 보여 줄 오류 메시지를 만들려면 순환을 검출하는 데 그치지 않고 실제 순환 경로를 뽑아야 하므로, DFS 기반 구현이 유리한 경우가 많다.

병렬 실행이 가능한 상황에서는 순서 하나를 고르는 대신 진입차수가 `0` 이 된 정점들을 한꺼번에 내보내는 층 분해를 쓴다. 층의 개수가 임계 경로의 길이이고, 각 층의 크기가 그 시점의 병렬도다.

## 계산 그래프

자동 미분은 순전파를 위상순으로, 역전파를 역위상순으로 수행한다. 데이터 처리 파이프라인, 작업 스케줄러, 스트림 처리 시스템의 실행 계획도 모두 DAG 위의 순회다. "계산을 DAG 로 표현한다" 는 설계는 실행 순서 결정, 중복 계산 제거, 증분 재계산을 한꺼번에 얻기 위한 것이다.

## 이 지도의 검증

이 문서 그래프는 선수지식에서 후속으로 가는 DAG 여야 한다. 간선을 더하기 전에 자식에서 부모로 가는 경로가 이미 있는지 검사하면 순환을 막을 수 있고, `dev/graph.mjs check-cycle` 이 하는 일이 그것이다. 기존 문서의 부모를 뒤늦게 바꾸는 경우에도 같은 검사로 충분하다.[^1]

[^1]: Robert Sedgewick and Kevin Wayne, *Algorithms*, Directed Graphs. 방향 순환 검출과 위상정렬. https://algs4.cs.princeton.edu/42digraph/
