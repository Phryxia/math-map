# Curry–Howard 대응

# 개요

Curry–Howard 대응은 논리와 계산이 같은 대상의 두 표기법이라고 말한다.

$$
\text{명제}=\text{타입},\qquad \text{증명}=\text{프로그램},\qquad \text{증명의 정규화}=\text{계산}
$$

$A \to B$ 의 증명은 $A$ 의 증명을 받아 $B$ 의 증명을 돌려주는 함수이고, $A \wedge B$ 의 증명은 두 증명의 순서쌍이다. [직관주의 논리](intuitionistic-logic.md)의 자연연역 규칙을 하나씩 적어 보면 [lambda calculus](lambda-calculus.md)의 타입 규칙과 글자 그대로 같다. 증명을 정리하는 절차(절단 제거)는 프로그램을 실행하는 절차(β-축약)와 같은 계산이다.

이 대응이 성립하려면 증명이 "구성" 이어야 한다. 고전 논리처럼 배중률을 공짜로 쓰면 증명에서 프로그램을 뽑아낼 수 없다. 직관주의 논리를 선수지식으로 두는 이유가 여기에 있고, 이 대응이 증명 보조기와 의존 타입 언어의 설계 원리가 되는 이유이기도 하다.

# 직관

## 증명을 값으로 보기

"$A$ 이면 $B$ 이다" 를 증명한다는 것은, $A$ 의 증명이 손에 들어왔을 때 $B$ 의 증명을 만들어 내는 절차를 제시하는 일이다. 이것은 함수의 정의와 구별되지 않는다. 마찬가지로 "$A$ 이고 $B$" 의 증명은 두 증명을 함께 쥐고 있는 것이므로 순서쌍이고, "$A$ 또는 $B$" 의 증명은 어느 쪽인지 표시된 증명 하나이므로 합 타입이다.

| 논리 | 타입 | 프로그램 |
|---|---|---|
| $A \to B$ | 함수 타입 | 람다 추상 |
| $A \wedge B$ | 곱 타입 | 순서쌍 |
| $A \vee B$ | 합 타입 | 태그 붙은 값 |
| $\top$ | 단위 타입 | 유일한 값 |
| $\bot$ | 빈 타입 | 값이 없음 |
| $\neg A$ | $A \to \bot$ | 빈 타입으로 가는 함수 |
| $\forall x.P(x)$ | 의존 함수 타입 | 인자에 따라 결과 타입이 변하는 함수 |
| $\exists x.P(x)$ | 의존 곱 타입 | 증인과 증명의 쌍 |

## 배중률이 없는 이유

$A \vee \neg A$ 의 증명은 "왼쪽" 또는 "오른쪽" 이라는 답을 내놓아야 한다. 임의의 명제에 대해 그 답을 주는 프로그램은 정지 문제를 푸는 것과 같으므로 존재할 수 없다. 직관주의 논리에서 배중률이 정리가 아닌 이유가 계산 쪽에서는 이렇게 보인다. 논리의 제약과 계산의 불가능성이 같은 사실의 두 얼굴이다.

# 정의

## 단순 타입 lambda calculus

타입은 기본 타입과 $\sigma \to \tau$ 로 만들어지고, 항의 타입은 문맥 $\Gamma$ (변수에 타입을 배정한 목록) 아래에서 판정된다. 규칙은 세 개뿐이다.

$$
\frac{(x:\sigma)\in\Gamma}{\Gamma\vdash x:\sigma}\qquad
\frac{\Gamma,x:\sigma\vdash t:\tau}{\Gamma\vdash\lambda x.t:\sigma\to\tau}\qquad
\frac{\Gamma\vdash t:\sigma\to\tau\quad\Gamma\vdash u:\sigma}{\Gamma\vdash t\,u:\tau}
$$

## 자연연역과의 대조

같은 세 규칙을 타입 이름만 명제로 바꿔 읽으면 자연연역의 가정, $\to$ 도입, $\to$ 제거가 된다.

$$
\frac{A\in\Gamma}{\Gamma\vdash A}\qquad
\frac{\Gamma,A\vdash B}{\Gamma\vdash A\to B}\qquad
\frac{\Gamma\vdash A\to B\quad\Gamma\vdash A}{\Gamma\vdash B}
$$

항을 지우면 증명이 되고, 증명에 항을 붙이면 프로그램이 된다. 대응은 비유가 아니라 표기의 동일성이다.

## 계산과 증명 정리

$\to$ 도입 바로 뒤에 $\to$ 제거가 오는 우회(절단)를 없애는 변환은 다음과 같다.

$$
(\lambda x.t)\,u\ \rightsquigarrow\ t[x:=u]
$$

왼쪽은 "가정을 세워 $B$ 를 얻은 뒤 그 가정을 실제 증명으로 채운" 상황이고, 오른쪽은 그 대입을 미리 수행한 직접 증명이다. 증명을 간소화하는 일과 프로그램을 한 걸음 실행하는 일이 같은 조작이다.

# 성질

## 정규화와 일관성

단순 타입 lambda calculus 는 강한 정규화 성질을 가진다. 타입이 붙은 항은 어떤 순서로 축약해도 유한 단계 안에 더 줄일 수 없는 형태에 도달한다. 논리 쪽으로 번역하면 모든 증명을 절단 없는 형태로 정리할 수 있다는 뜻이고, 여기서 일관성이 따라온다. $\bot$ 의 절단 없는 증명은 형태상 존재할 수 없으므로 $\bot$ 를 증명할 수 없다. 무한 재귀를 허용하는 타입 체계는 $\bot$ 를 증명할 수 있게 되어 논리로서는 무너진다. 프로그래밍 언어의 일반 재귀가 논리적으로는 모순이라는 이 사실이, 증명 보조기가 재귀를 엄격히 제한하는 이유다.

## 고전 논리는 제어 연산자

배중률이나 이중부정 제거를 추가하면 대응이 깨지는 것이 아니라 다른 프로그램 개념이 붙는다. Griffin 이 보인 것처럼 Peirce 법칙 $((A \to B) \to A) \to A$ 는 `call/cc` 같은 제어 연산자의 타입이다. 고전적 증명에서 뽑아낸 프로그램은 계산 도중 이전 지점으로 되돌아가 답을 바꾸는 방식으로 동작한다. "존재를 보였지만 어떤 것인지는 모른다" 는 고전적 증명의 성격이 계산에서는 백트래킹으로 나타난다.

## 세 번째 꼭짓점

대응에는 범주론적 판본이 있다. 단순 타입 lambda calculus 는 데카르트 닫힌 범주의 내부 언어이고, 곱 타입은 곱, 함수 타입은 지수 대상에 해당한다. 논리·계산·범주가 이루는 이 삼각 대응을 Curry–Howard–Lambek 대응이라 부른다.

## 코드로 보는 대응

조합자 $K$, $S$ 의 타입이 그대로 함의 논리의 두 공리이고, `curry`/`uncurry` 가 곱과 함수 사이의 대응을 준다.

```python
# K : A → (B → A)          "A 가 참이면 무엇을 가정해도 A 다"
K = lambda a: lambda b: a

# S : (A → B → C) → (A → B) → A → C     자기분배 공리
S = lambda f: lambda g: lambda x: f(x)(g(x))

# I : A → A 는 S 와 K 만으로 얻어진다. 즉 항등증명은 두 공리의 따름정리다
I = S(K)(K(K))
print(K(7)(9), S(lambda x: lambda y: x + y)(lambda x: x * 10)(3), I(42))
# 7 33 42

# (A ∧ B → C) ↔ (A → B → C) : 곱 타입과 함수 타입의 수반
curry   = lambda f: lambda a: lambda b: f((a, b))
uncurry = lambda f: lambda p: f(p[0])(p[1])
f = lambda p: p[0] + p[1]
print(curry(f)(2)(3), uncurry(curry(f))((2, 3)))   # 5 5

# A ∨ ¬A 에 대응하는 항은 쓸 수 없다. 어느 쪽인지 고를 방법이 없기 때문이다
```

$I=S(K)(K(K))$ 가 실제로 항등함수로 동작한다는 것은, 논리 쪽에서 $A \to A$ 가 두 공리로부터 유도된다는 사실의 실행 가능한 판본이다. 마지막 줄이 이 대응의 경계를 보여 준다. 참·거짓을 아는 것과 어느 쪽인지 계산해 내는 것은 다르다.

# 활용

## 증명 보조기

Coq, Lean, Agda 는 이 대응을 그대로 구현한 시스템이다. 정리를 타입으로 쓰고 증명을 그 타입의 항으로 만들며, 타입 검사기가 증명 검사기 노릇을 한다. 증명의 정당성 검사가 기계적인 타입 검사로 환원되므로 신뢰 기반이 작은 핵심부로 좁혀진다. 4색 정리와 Feit–Thompson 정리의 기계 검증, CompCert 컴파일러의 정확성 증명이 이 방식으로 이루어졌다.

## 프로그램 추출과 명세

구성적 증명에서 프로그램을 자동으로 뽑아낼 수 있다. "모든 입력 $x$ 에 대해 조건 $P(x,y)$ 를 만족하는 $y$ 가 존재한다" 를 구성적으로 증명하면, 그 증명 자체가 $y$ 를 계산하는 알고리즘이고 명세를 만족함이 이미 보장되어 있다. 사후 검증 대신 명세에서 구현이 따라 나오는 순서가 된다.

## 타입 시스템 설계

프로그래밍 언어의 타입 기능은 대개 논리 쪽의 대응물을 가진다. 다형성은 2 차 논리의 전칭 한정, 의존 타입은 술어논리의 한정기호, 선형 타입은 자원을 한 번만 쓰는 선형논리에 대응한다. 새 타입 기능을 설계할 때 대응하는 논리가 일관적인지 확인하면 체계가 무너지는 경우를 미리 걸러낼 수 있다.
