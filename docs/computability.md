# 계산 가능성과 정지 문제

# 개요

"기계적으로 풀 수 있다" 는 말을 수학의 대상으로 만들면 무슨 일이 벌어지는가. 계산 가능성 이론은 이 질문에서 출발해, 알고리즘이라는 비형식적 개념에 정확한 정의를 부여하고 그 정의로 "어떤 알고리즘도 없다" 를 증명한다.

이 이론이 놀라운 지점은 한계가 자원 부족에서 오지 않는다는 데 있다. 시간과 메모리를 무한히 줘도 풀리지 않는 문제가 존재하며, 그 증명은 [Cantor의 대각선 논증](cardinality.md)과 같은 형태다. 프로그램은 유한 문자열이므로 가산 개뿐인데 판정해야 할 대상은 그보다 많다는 셈이 밑바탕에 있고, 정지 문제는 그 과잉을 구체적인 한 문제로 지목한 것이다. [함수](functions.md)의 전사·단사 개념과 [증명](proofs.md)의 귀류법만 알면 그 핵심을 따라갈 수 있다.

# 직관

## 대각선 논증의 재등장

실수가 가산이 아니라는 증명은 목록에 없는 실수를 "각 항목과 한 자리씩 다르게" 만들어 낸다. 정지 문제의 증명도 똑같다. 모든 프로그램을 나열한 뒤 $i$ 번째 프로그램이 $i$ 번째 입력에서 하는 행동과 정반대로 행동하는 프로그램을 만든다. 그 프로그램은 목록에 없어야 하는데, 유한한 코드로 적혔으니 목록에 있어야 한다.

차이는 결론의 위치뿐이다. Cantor 에서는 "목록이 전부일 수 없다" 로 끝나고, 여기서는 목록이 전부인 것이 분명하므로 "그 프로그램을 만들 수 있게 해 준 가정, 곧 판정기의 존재가 거짓" 이 된다.

## 자기 언급이 필요한 이유

정지 문제가 어려운 이유를 "프로그램이 오래 돌 수도 있어서" 로 이해하면 안 된다. 시간 제한은 본질이 아니다. 핵심은 판정기가 존재하면 그 판정기를 자기 자신에 대해 쓰는 프로그램을 만들 수 있고, 그 프로그램이 "판정 결과를 배신하도록" 설계될 수 있다는 점이다. 거짓말쟁이 역설, [Gödel 불완전성 정리](godel-incompleteness.md), Russell 역설이 모두 같은 구조를 공유한다.

## 반쯤은 풀린다

정지하는 입력만 골라내는 것은 쉽다. 그냥 돌려 보면 된다. 멈추면 "예" 라고 답하고, 안 멈추면 영원히 답하지 않는다. 이 비대칭이 결정 가능과 인식 가능(recursively enumerable)의 차이이며, 계산 불가능성의 세계에서 가장 먼저 배우는 구분이다. 답이 "예" 일 때만 확인할 수 있는 절차는 증명 검색, 타입 추론, 정리 증명기에서 계속 나타난다.

# 정의

## Turing machine

계산 모델로 Turing machine 을 쓴다. 유한한 상태 집합, 유한한 기호 집합, 양방향으로 확장되는 테이프, 기호 하나를 읽고 쓰며 좌우로 이동하는 헤드, 그리고 유한한 전이 규칙으로 이루어진다. 한 단계의 행동은 현재 상태와 읽은 기호만으로 결정된다.

```python
def step(tape, head, state, delta):
    """delta[(state, symbol)] = (state', symbol', move). 정지 상태면 None."""
    key = (state, tape.get(head, "_"))
    if key not in delta:
        return None
    state2, write, move = delta[key]
    tape[head] = write
    return tape, head + move, state2
```

전이 규칙이 유한하다는 것, 한 단계가 국소적이라는 것, 테이프만 무한하다는 것이 전부다. 이 빈약한 모델이 Lambda calculus, 재귀함수, 레지스터 기계, 실제 프로그래밍 언어와 정확히 같은 계산력을 가진다는 사실이 반복 확인되었고, 이를 근거로 "계산 가능 = Turing machine 으로 계산 가능" 을 받아들이는 것이 Church–Turing 논제다. 이는 정리가 아니라 비형식적 개념과 형식적 정의를 잇는 약속이다.

## 계산 가능, 결정 가능, 인식 가능

입출력은 유한 문자열로 부호화한다. 모든 유효한 입력에서 멈추어 지정한 출력을 내는 기계가 있으면 그 함수는 계산 가능하다. 어떤 입력에서 멈추지 않는 기계는 부분함수를 계산한다.

결정 문제는 입력마다 예 또는 아니오를 요구한다. 언어 $L \subseteq \Sigma^*$ 에 대해 세 층위를 구분한다.

| 층위 | 조건 |
|---|---|
| 결정 가능 | 모든 입력에서 멈추고 $L$ 의 소속 여부를 정확히 답하는 기계가 있다 |
| 인식 가능 | $x \in L$ 이면 멈추고 수락하는 기계가 있다. $x \notin L$ 이면 거부하거나 영영 안 멈춘다 |
| 공인식 가능 | 여집합이 인식 가능하다 |

$L$ 이 결정 가능한 것과 $L$, $L^{\mathrm c}$ 가 모두 인식 가능한 것은 동치다. 두 기계를 번갈아 한 단계씩 돌리면 반드시 한쪽이 먼저 수락하기 때문이다.

## 보편 기계와 부호화

기계의 유한한 기술 자체가 문자열이므로 기계를 다른 기계의 입력으로 넣을 수 있다. 임의의 기계 기술 $\langle M \rangle$ 과 입력 $x$ 를 받아 $M(x)$ 를 그대로 흉내 내는 보편 Turing machine 이 존재하며, 이것이 "프로그램을 데이터로 다룬다" 는 발상의 원형이자 저장 프로그램 컴퓨터의 이론적 근거다. 자기 언급이 가능해지는 것도 이 부호화 덕이다.

# 성질

## 정지 문제는 결정 불가능하다

정지 문제는 프로그램 $p$ 와 입력 $x$ 를 받아 $p$ 가 $x$ 에서 언젠가 멈추는지 묻는다.

**정리.** 모든 $(p,x)$ 에 대해 정지 여부를 정확히 판정하고 항상 멈추는 알고리즘은 없다.

그런 판정기 $H$ 가 있다고 하자. $H(q,x)$ 는 멈추면 $1$, 아니면 $0$ 을 출력하고 자신은 언제나 멈춘다. 이제 프로그램 $D$ 를 정의한다. $D$ 는 프로그램 문자열 $q$ 를 받아 $H(q,q)$ 를 계산하고, 결과가 $1$ 이면 무한 반복하며 $0$ 이면 즉시 멈춘다.

$D$ 의 프로그램 문자열을 $d$ 라 하고 $D(d)$ 를 보면

$$
D(d)\text{ halts}\iff H(d,d)=0\iff D(d)\text{ does not halt}
$$

이므로 모순이다. $D$ 는 $H$ 와 몇 줄의 분기만으로 구성되므로 $H$ 가 존재하면 $D$ 도 반드시 존재한다. 따라서 $H$ 가 없다.

정지 문제는 인식 가능하다. 주어진 프로그램을 그냥 실행하면 멈추는 경우 유한 시간에 확인된다. 따라서 그 여집합은 인식 가능하지 않다. 인식 가능과 결정 가능이 다르다는 것을 보여 주는 표준 예다.

## 환원이 불가능성을 퍼뜨린다

문제 $A$ 를 푸는 일이 문제 $B$ 를 푸는 일로 번역되면, 곧 $A$ 의 입력을 $B$ 의 입력으로 바꾸는 계산 가능한 함수 $f$ 가 있어 $x \in A \iff f(x) \in B$ 이면 $A \le_m B$ 라 쓴다. $B$ 가 결정 가능하면 $A$ 도 결정 가능하므로, 대우로 $A$ 가 결정 불가능하면 $B$ 도 그렇다.

새 문제의 결정 불가능성은 대각선 논증을 다시 하는 대신 정지 문제를 환원해 보인다. 이 방식으로 Post 대응 문제, Diophantus 방정식의 정수해 존재성(Hilbert 10번), 문맥자유 문법의 모호성, 타일링 문제가 차례로 결정 불가능으로 판명되었다. 프로그램의 의미적 성질에 대해서는 [Rice 정리](rice-theorem.md)가 "자명하지 않은 모든 성질" 을 한꺼번에 결정 불가능으로 몰아넣는다.

## 계산 불가능성의 층

정지 문제를 공짜로 답해 주는 신탁을 붙인 기계를 생각할 수 있다. 그런 기계에게도 자기 층위의 정지 문제는 여전히 결정 불가능하고, 이를 반복하면 끝없이 올라가는 난이도의 사다리가 생긴다. Turing 차수라 부르는 이 구조는 결정 불가능성이 하나의 벽이 아니라 무한히 쌓인 층이라는 것을 보여 준다.

## 결정 불가능성과 복잡도는 다른 질문이다

계산 가능성은 "알고리즘이 있는가" 를 묻고 복잡도는 "얼마나 비싼가" 를 묻는다. [P 대 NP 문제](p-np.md)는 둘 다 계산 가능한 문제들 사이의 비용 차이를 다루며 아직 미해결이다. 반면 정지 문제의 불가능성은 증명된 결과다. "어렵다" 와 "불가능하다" 를 섞어 쓰지 않아야 한다.

# 활용

## 정적 분석의 원리적 한계

"이 프로그램이 널 참조를 하는가", "이 루프가 종료하는가", "이 코드가 도달 가능한가" 는 모두 Rice 정리의 적용 대상이라 완전한 자동 판정기가 없다. 그래서 실제 도구는 완전성 대신 건전성을 택한다. 타입 검사기와 정적 분석기는 안전하지 않은 프로그램을 거부하되 안전한 프로그램도 일부 거부하고, 종료 증명기는 "종료한다" 를 보이거나 포기하며 "종료하지 않는다" 를 단정하지 않는다.

한계는 개별 프로그램에 대한 것이 아니다. 특정 프로그램의 종료는 얼마든지 증명할 수 있다. 모든 프로그램을 처리하는 하나의 판정기가 없을 뿐이다.

## 논리와의 연결

충분히 강한 형식 체계에서 증명 가능성을 판정하는 문제는 결정 불가능하다. 체계가 자기 안에 계산을 흉내 낼 수 있으면 정지 문제가 그 안으로 환원되기 때문이다. 여기서 한 걸음 더 나가면 참이지만 증명할 수 없는 명제의 존재, 곧 [Gödel 불완전성 정리](godel-incompleteness.md)가 나온다. 두 정리는 같은 자기 언급 기법의 서로 다른 얼굴이다.

## 모델의 계층

Turing machine 의 자원을 제한하면 계산력이 줄어든다. 테이프 대신 유한 상태만 남기면 [유한 오토마타](finite-automata.md)가 되고 정규언어만 인식한다. 스택을 하나 붙이면 문맥자유 언어가 된다. 이 계층에서는 정지 문제에 해당하는 질문들이 다시 결정 가능해지며, 그래서 정규표현식과 문법은 안전하게 자동 분석할 수 있다. 표현력을 포기하는 대신 판정 가능성을 얻는 이 거래가 도메인 특화 언어 설계의 핵심이다.[^1]

[^1]: Stanford Encyclopedia of Philosophy, *Computability and Complexity*. Turing machine 의 정의, 정지 문제, Church–Turing 논제와 복잡도의 구분. https://plato.stanford.edu/entries/computability/
